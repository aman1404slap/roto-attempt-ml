# S3 — taking away which shape is which

*Read [s0.md](s0.md), then [s1.md](s1.md), then [s2.md](s2.md). This is the one they were all
building towards.*

*For each training attempt and what it cost, see [s3-attempts.md](s3-attempts.md).*

---

## The one-sentence version

The model has been keeping a private notebook — one memory slot per shape, per layer. S3 takes
the notebook away.

## What was in the notebook

Every shape in every layer had its own slot: *shape #7 of `ts_020876__Red`* meant that shape and
nothing else. It is how the model knew which shape it was drawing — and it is why, until now, the
model could only work on layers it had already been trained on. A new shot has no slots, so there
was nothing to look up.

S3 replaces the whole notebook with **one shared set of 256 blank slots**, used for every layer in
the dataset. Nothing in a slot names a shape. Everything layer-specific has to be worked out from
the picture.

## Why this is the rest of the project, not the next step

We can measure exactly what the notebook was worth. Take the finished S2 model and wipe it, leave
everything else intact:

| | picture quality |
|---|---|
| S2, with its notebook | **0.9652** |
| the same model, notebook wiped | **0.0377** |

Everything the earlier stages achieved sits on top of that notebook. **S3's whole job is to
replace it with something derived from looking.**

It is also the difference between a demo and a tool. A tool has to work on a shot it has never
seen. Until S3, the honest answer to "what does it do on a new shot?" was *nothing at all*.

---

## The trap we found before starting

S3's pass mark was: *the picture must reach 0.95 on layers it has never seen.*

We checked whether that was worth anything, the same way we checked S2's. Take the artist's own
cutout, trace around its outline, resample to a sensible number of control points, rebuild it as
real shapes, render it back.

| | shapes used | score on held-out layers |
|---|---|---|
| trace each blob's outline | **1.2** | **0.9697** |

The artist used between 1 and 247 shapes. The trace uses **1.2**, understands nothing, and would
be useless to an artist — you cannot edit a single blob the way you edit a breakdown. And it
clears the bar.

That is not a flaw in the measurement; it is the measurement doing its job. Picture quality is
deliberately **blind to how you carved the picture up** — that is what stops us punishing an
artist who uses 20 shapes where another uses 40. It is only a hole when it is the *whole* pass
mark, at the one stage where the carving-up is the entire task.

**So the pass mark was changed before any code was written:** the picture must beat the traced
outline, *and* the answer has to look like roto — roughly the right number of shapes, points and
keyframes. Those became hard requirements rather than nice-to-haves.

---

## What we have found so far

**The mechanism works.** On layers it has seen, taking the notebook away costs about 0.027 of
picture quality — 0.9652 down to 0.9385. Much less than expected.

**And the memorising really was memorising.** The gap between frames it trained on and frames it
did not collapsed from 0.0108 to **0.0027** when the notebook went. It is no longer remembering;
it is looking.

**But it does not generalise.** On the four shots it has never seen, it scores **0.2031** —
against 0.9697 for tracing the outline by hand. The pictures in the diary show it plainly: a
small scribble where a large shape should be.

**And the failure points somewhere specific.** Two numbers side by side:

- on unseen **frames** of a shot it knows: essentially perfect
- on an unseen **shot**: near-total failure

It generalises within a shot and not across shots — on **eight shots** of training data. That is
what too little data looks like, not what a broken idea looks like. The next question is whether
more shots fix it.

---

## What "done" would look like

Three attempts were planned: replace the notebook, then change what the model is graded on, then
try a different rule for deciding which slot holds which shape. The first is done. Whether the
other two are the right next move — or whether more data is — is the open question.

**And if it does not work, that is still a result**, provided it is written down with the number
and the reason. That is the rule this project runs on, and it is why the diary records every
attempt rather than only the ones that worked.
